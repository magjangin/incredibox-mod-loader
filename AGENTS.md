# Incredibox ModLoader

## 1. Target Game & Version
- **Game:** Incredibox (Steam PC, v1.2.9)
- **Install Path:** `H:\steam\steamapps\common\Incredibox\Incredibox_steam.exe`
- **Modded Runtime Path:** `H:\steam\steamapps\common\Incredibox\Modded\`
- **Runtime:** Electron (`electron-builder` NSIS portable wrapper containing `$PLUGINSDIR\app-64.7z`, which holds `Incredibox.exe` + `resources\app.asar`)
- **Electron Fuses:** `EnableEmbeddedAsarIntegrityValidation=disabled`, `OnlyLoadAppFromAsar=disabled`, `EnableNodeOptionsEnvironmentVariable=enabled`, `EnableNodeCliInspectArguments=enabled`, `RunAsNode=enabled`
- **Version pinning: none.** Steam appid 1545450, buildid 21134016, `AutoUpdateBehavior 0` (auto-update ON); no DepotDownloader download and no `.acf` lock. An update restores the original `Incredibox_steam.exe` (re-run the installer / `setup-game.ps1`). If an update changes `script.min.js`, the engine patch (§3.0.4) checks that each pattern matches exactly once and otherwise leaves the vanilla script in place, so the game still starts (only >20-icon packs lose their layout).
- **Runtime backend:** not Unity (no Mono / Il2Cpp). The game logic is obfuscated JavaScript: `resources\app\src\js\script.min.js` (obfuscator.io string array, see §3.0.2 for decoding) and `src/elec-index.js` (main process). Readable copies are made on demand in a scratch folder, never committed.
- **ModLoader version:** `LOADER_VERSION` in `modloader/main.js` (0.3.1). The installer takes its assembly version from it, and the badge shows it.

## 2. Design & Rationale
- **Bootstrap Approach (Method A):** Unpacks `app-64.7z` once into `Modded\` and unpacks `resources\app.asar` (985 files) to `resources\app\` (renaming `app.asar` to `app.asar.bak`). This avoids 204MB self-extraction on every launch and allows direct modification without ASAR repacking.
- **Entry Hook & Steam Bypass:** `resources\app\package.json` `"main"` is changed from `src/elec-index.js` to `modloader/main.js`, which preserves `console` methods before `src/elec-index.js` obfuscation overwrites them, sets `PORTABLE_EXECUTABLE_DIR` and `--arg=arp` (`btoa(electron.vars.arg) === "YXJw"` required by `script.min.js`), scans `Mods/` and `ApkMods/` next to `Incredibox.exe`, attaches `BrowserWindow` hooks (`F12` / `Ctrl+Shift+I` DevTools + `dom-ready` renderer injection + `app.html?v=<versionId>` auto-redirect to unpacked APK mods), and then `require('../src/elec-index.js')`.
- **APK Mod Playback (100-char / 10-polo):** vanilla PC Incredibox v1.2.9 hardcodes 20 icons and 7 polos in `script.min.js` (since ModLoader 0.3.0 the engine patch in §3.0.4 lifts that for PC packs; APK mods still run their own engine). `unpack-apk-mod.js` extracts `assets/www/` (neutralizing `cordova.js` so `DOMContentLoaded` runs on desktop) into `Modded\ApkMods\<ModName>\`. `modloader/renderer.js` provides `F10` launch/return controls, 90% default screen scaling, a 20×5 centered picto grid with 5-icon group gaps (`layoutApkPictos`), and (0.3.1) a home-screen "back to PC" button (`addApkHomeBackButton`, §3.0.1).

## 3. Key Files
- `modloader/main.js` — Main-process bootstrap, `Mods/` scanner, logger (`Mods/modloader.log`), DevTools shortcut, and renderer injector.
- `modloader/engine-patch.js` — PC engine patch for >20 icons / configurable `nbpolo` (§3.0.4). Pure `patchEngineSource(text)` + `ensurePcEnginePatched(srcDir, logger)`, called by `main.js` before `elec-index.js` loads. `main.js` `require`s it, so every deploy must copy the whole `modloader\` folder (setup and installer both do).
- `modloader/renderer.js` — Renderer `window.IncrediboxModLoader` API, CSS/JS mod executor, bottom-left badge, `F10` mod list overlay, APK-mode scaling/replay-seek fix, and the PC 100p picto grid (`window.__mlLayoutPcPictos`). It is injected as one string by `executeJavaScript`, so it must stay a single self-contained file.
- `scripts/extract-asar.js` — Zero-dependency Node.js ASAR extractor (`extractAsar(asar, dest, subDir?)`). Rejects unsafe entry names, skips `unpacked` and `link` entries.
- `scripts/setup-game.ps1` — Automated extractor/installer using Bandizip (`bz.exe`) + Node.js. `-GameDir` auto-detects via `HKCU\Software\Valve\Steam\SteamPath` + `steamapps\libraryfolders.vdf`; `-TargetDir` defaults to `<GameDir>\Modded`; `-Bandizip` defaults to `$env:BANDIZIP` > Program Files > PATH.
- `scripts/lib/common.js` — Shared `stableVersionId` / `parseAppJs` / `findBandizip` / `findGameDir` / `findModdedDir` (env overrides: `BANDIZIP`, `INCREDIBOX_DIR`), data-URL helpers, `isGameRunning()` and `installIncredimod()` (§3.1). **`stableVersionId` must never change**: existing `apkmod.json` `versionId`s (e.g. `Armed` = 9533019) and imported `incredimods/<versionId>.json` depend on it for the `app.html?v=` redirect.
- `scripts/import-apk.js` — Converts Android Incredibox mod APKs (`assets/www/asset-v*`) into PC `incredimods/<versionId>.json` + `localmods.json` entries under `%APPDATA%\Incredibox\incredimods\`. Keeps the APK's `nbpolo`. Refuses while the game runs (`--force` overrides).
- `scripts/unpack-apk-mod.js` — Extracts full `assets/www/` from Android mod APKs into `Modded\ApkMods\<ModName>\` for 100-character / custom-engine playback via the ModLoader `F10` overlay.
- `scripts/sb3-to-incredimod/` — Converts a Sprunki-style Scratch `.sb3` into a PC incredimod: Scratch timeline interpreter, headless-Edge SVG rendering, ffmpeg A/B loops, and the pack installer.
- `scripts/build-100p-mod.js` — Multi-mod 100-character / 10-polo incredimod builder combining PC incredimods, APKs, ASAR ZIPs, and unpacked dirs into one unified-BPM pack. Config template: `scripts/build-100p-mod.example.json` (§3.0.4).
- `installer/IncrediboxModLoaderInstaller.cs` + `scripts/build-installer.ps1` — Single-exe GUI/CLI installer (no Node/Bandizip needed on Windows 11), see §3.0.0.
- `launcher/IncrediboxLauncher.cs` — Steam `Incredibox_steam.exe` replacement that starts `Modded\Incredibox.exe`.
- `mods-example/hello-mod/` — Sample mod manifest (`mod.json`) and `renderer.js`.

## 3.0 Steam Launcher (Incredibox_steam.exe replacement)
- **Why:** users launching from Steam got the vanilla game (same `%APPDATA%\Incredibox\incredimods` list, so imported mods appear but no loader/badge) and could not tell whether mods were applied.
- **How:** `setup-game.ps1` step 6 compiles `launcher/IncrediboxLauncher.cs` with `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (C# 5 — no `$""` interpolation) and installs it as `<GameDir>\Incredibox_steam.exe`; the real Steam exe is moved to `Incredibox_steam.original.exe`. Launcher starts `Modded\Incredibox.exe` with args passed through, waits for exit (Steam playtime/"Running" state), Shift held → original exe, Modded missing → original + warning.
- **Detection:** launcher is identified by `VersionInfo.ProductName == "Incredibox ModLoader Launcher"`. If `Incredibox_steam.exe` is *not* the launcher (first install, Steam update or verify), setup treats it as the newest original, replaces the `.original.exe` backup and extracts from it; otherwise it extracts from `.original.exe`.
- **Steam appid:** 1545450 (`appmanifest_1545450.acf`, buildid 21134016, `AutoUpdateBehavior 0` = auto-update ON → an update restores the original exe; re-run setup). `-Uninstall` restores the original; `-NoLauncher` skips step 6. Launcher only supports `TargetDir = <GameDir>\Modded`.
- **Verified 2026-11-18:** `steam://rungameid/1545450` → `Incredibox_steam.exe` (launcher, parent steam.exe) → `Modded\Incredibox.exe`, loader injected; closing the game window ends the launcher. `--remote-debugging-port=9333` passed through the launcher reaches Electron.
- **Verified by the user:** pressing ▶ on the *Imported* "Armed" cover (PC incredimod v=9533019) fires `will-navigate` to `src/app.html?v=9533019`, which opens the Armed APK window. `script.min.js` is obfuscated with an obfuscator.io string array (`a4`/`a5`, offset 0x122). To read it, decode the array in a `vm` context; there are no plain `app.html` literals.

## 3.0.0 Single-exe Installer (MelonLoader-style, 2026-11-19)
- **Files:** `installer/IncrediboxModLoaderInstaller.cs` (WinForms + CLI), `scripts/build-installer.ps1` → `build/IncrediboxModLoader-Setup.exe` (~86 KB in 0.3.0, `build/` is gitignored). Built with the Windows .NET Framework 4 `csc.exe` (C# 5). Payload = manifest resources `payload/modloader/*`, `payload/mods/hello-mod/*`, `payload/launcher/IncrediboxLauncher.cs` and a prebuilt launcher `payload/launcher/Incredibox_steam.exe`. Assembly version comes from `LOADER_VERSION` in `modloader/main.js`.
- **Why no Node/Bandizip:** electron-builder stores `$PLUGINSDIR\app-64.7z` **uncompressed** in the NSIS data, so the installer carves it from the Steam exe. It finds the 7z signature `37 7A BC AF 27 1C`, checks the start-header CRC32 and the end bound, and uses `32 + NextHeaderOffset + NextHeaderSize` as the length (v1.2.9: offset 58165, 204,447,926 bytes). Windows 11 `System32\tar.exe` (bsdtar 3.8.9 with liblzma) extracts it. The resulting `app.asar` was byte-identical to the Bandizip-extracted one. Fallbacks, in order: `7-Zip\7z.exe`, then `$env:BANDIZIP` / `Bandizip\bz.exe` (Windows 10's tar 3.5.2 has no liblzma). The temp archive goes in `<target>\.installer-tmp` (same drive) and is deleted afterwards.
- **ASAR:** ported to C# with `JavaScriptSerializer` (`System.Web.Extensions`). File names are checked (no `..`, separators or invalid chars, and the path must stay under the destination). `unpacked` entries are copied from `app.asar.unpacked` (v1.2.9 has none) and `link` entries are skipped. `package.json` gets a regex replace of `"main"` only (original formatting, UTF-8 without BOM). `setup-game.ps1` re-serializes the file with a BOM instead; the parsed content is identical.
- **Launcher:** compiled at install time with CodeDom (`CSharpCodeProvider`) and `/win32icon:<Modded>\resources\app\src\favicon.ico`, so the game icon is never redistributed. If that fails, the embedded prebuilt (default icon) is used. Same replace/backup and launcher-detection rules as `setup-game.ps1` (§3.0).
- **Re-install keeps** `Mods/`, `ApkMods/`, `Recordings/` and an edited `Mods/hello-mod` (the sample is only written when the folder is missing). Only `resources/app` is wiped.
- **Verified offline (2026-11-19):** fake game dir `H:\source\incredibox-work\installer-test` with a **hardlink** to `Incredibox_steam.original.exe` (no 200 MB copy; the installer only renames, never writes into it). `--install` took about 10 s. `diff -r` against the real `Modded` showed only `package.json` (format) and user `Recordings/`. modloader matched the repo. Launcher ProductName was correct and `.original.exe` was kept. Re-install read from `.original.exe` and kept user files. `--uninstall` restored the exe, and a second uninstall was a no-op. The GUI window was captured with PrintWindow; no button was clicked. **Not verified:** the 7-Zip/Bandizip fallback, the prebuilt-launcher fallback, Windows 10, and in-game play through the installer-made runtime (identical files to the verified runtime).
- **Not included:** APK import/unpack in the installer. The scripts still need Bandizip for the APK zip. `ELECTRON_RUN_AS_NODE=1 Modded\Incredibox.exe <script>` could replace Node (the RunAsNode fuse is on), but that is untested.

## 3.0.1 APK Mod Storage Isolation (2026-11-18 save-loss incident)
- **Incident:** a mix the user saved in the Armed APK engine (`mix-<20-hex>-v1`) vanished. Cause: APK engines were loaded in the PC window on the same `file://` origin, so they shared localStorage with the PC game. The PC `script.min.js` runs `deleteOldLocalMixes()` at startup, which deletes every `mix-`/`fav-` entry whose `link` contains both digits and letters, so it deleted the APK mix (22:12:55, same batch as PC `timer-restore`). The APK engine also overwrote the PC `user-lang` (ko → en-US).
- **Fix (main.js):** APK mods now open in their **own BrowserWindow** with `partition: persist:apkmod-<id>-<sha1-8>` (separate localStorage). PC window is hidden while it is open and shown again on close. Same preload as the PC window (`getLastWebPreferences()`, fallback `src/elec-preload.js`) because APK engines call `_electron.machine.machineIdSync()` on desktop. Navigation rules (`will-navigate`): `app.html?v=<versionId>` or any URL under `ApkMods/<mod>/www/` → open that mod's window; inside an APK window, navigating to `resources/app/src/*` (Back to PC) → close the window.
- **Saves backup:** every APK window dom-ready / 30 s / close → `ApkMods/<mod>/saves/backup-latest.json` (+ `backup-previous.json`) and `backup-archive.json` (union, never removes keys).
- **Restore:** `ApkMods/<mod>/restore/*.json` = `{"key","value"}` is written into that mod's partition if the key is missing, then moved to `restore/done/`. The recovered Armed mix was staged there. The raw recovery also lives at `_save-backup/20261118-2230/recovered-mix-*.json` (gitignored).
- **Recovery technique:** Chromium localStorage = LevelDB at `%APPDATA%\Incredibox\Local Storage\leveldb`. Deleted values can survive in an older `.ldb` table until compaction. Parse the SSTable (footer → index block → snappy data blocks; key = `_file://\0\x01<key>`, value byte 0 = `\x01` latin1 / `\x00` UTF-16LE). Back up the folder **before** launching the game again.
- **APK home "back to PC" button (0.3.1, 2026-11-19):** the user reported that the two top-left home buttons (mod list `#home-bt-modlist`, mod credits `#home-bt-modcredit`) "disappear" in the APK window. Not a bug: they exist only in the PC `app.html` (`#home-bt-modlist/-modcredit/-modshare`); the Android engine's home has only info / param / switch / play / list. `renderer.js` `addApkHomeBackButton()` (APK mode only) appends `div#ml-home-bt-backpc.bt` to `#home` with a self-drawn left-arrow SVG (no game icon copied). Being a `.bt` inside `#home`, it takes the engine's theme (`#home .bt .bck` = `var(--col1)`, hover `--col3`). CSS mirrors `#home-bt-param` (`top/left: 44px`, 44 px; `body.mobile` 60 px, `body.ultrawide` +50 px, hidden in `body.miniPlayer` / `.expo`). The engine fades its home buttons in by adding `animate` once (`$homeBtInfo...addClass("animate")`), so a `MutationObserver` on `#home-bt-info`'s class copies `animate` to the new button; if `#home-bt-info` is missing the button is shown at once. Click → `api.backToPc()` → `will-navigate` to `src/*` closes the APK window and shows the hidden PC window again. **Verified offline:** a fake APK home page with the real Armed `style.min.css` in headless Edge: hidden (opacity 0) before `animate`, then at the mirror position of `#home-bt-param` with the same size and colour, `elementFromPoint` hits the button, and a click navigates to `pcIndexUrl`. **In game (user, 2026-11-19):** the button appeared, but pressing it closed the APK window and left a **black PC window**.
- **Black PC window after an APK mod (fixed in 0.3.1):** before the PC game navigates to `app.html?v=<id>` it calls `tk()` (adds `show` to `#lock-all`, an input lock) and fades `#fade-all` in (`hE(nX,"fadeIn","opacity",()=>gH(url))`, found in the decoded v1.2.9 script at the cover ▶ / mod-list play / version switch handlers). `will-navigate` cancels that navigation to open the APK window, so the PC page stays black and locked while hidden, and `showPcWindow()` used to just show it again. This was there since the APK window split (§3.0.1); the earlier in-game check only covered opening the APK window. Fix (`main.js`): an intercepted navigation from the PC window sets `win.__reloadOnReturn`, and `showPcWindow()` then calls `webContents.reload()` (same URL: `index.html` or the `app.html?v=` the user came from, i.e. its home screen) before `show()`. Applies to every way back: the home button, `F10` → Back to PC, and closing the APK window. Log line: `Reloading PC window after APK mod (<url>).` Undoing the classes in the page (`#fade-all.fadeIn`, `#lock-all.show`, `pop-switch` icon `open clicked`) was rejected: it depends on obfuscated engine state. **Verified offline** with a stubbed `electron` (PC `will-navigate` to `app.html?v=9533019` intercepted → APK window loads `ApkMods/Armed/www/app.html?v=1` → its back-to-PC navigation is intercepted and the window closes → exactly one `pc.reload` of the mashup URL, then `pc.show`). **Verified in game by the user (2026-11-19, 0.3.1):** the home button brings the PC window back ("됐다"); the log shows `Reloading PC window after APK mod (…/src/index.html)`, a new injection into `index.html`, and then a normal switch to another version (`app.html?v=9774514`).
- `unpack-apk-mod.js` now replaces only `www/` and `apkmod.json`; `saves/` and `restore/` are user data and must survive re-unpacking.
- **Known APK engine behaviour (not ours):** `getStatMixOnline` deletes *online* mixes the server does not return; `checkNews` `eval`s server-sent `msg`.
- **Verified:** offline with stubbed Electron (8 checks), then **in game by the user (2026-11-18 23:17)**. Imported Armed ▶ opened the APK window (partition `persist:apkmod-Armed-32caa310`), log showed `Restore …: restored` + `Saves backed up (1 mix/fav)`, and the mix is back in MY MIX.

## 3.0.2 PC Incredimod Format (reverse-engineered from v1.2.9 `script.min.js`, verified in game 2026-11-19)
- **Decoding the game JS:** `script.min.js` uses an obfuscator.io string array (`a4()` array, `a5(i)` = `array[i-0x122]`, rotation IIFE `(a4,0x72700)`). Run those three pieces in a `vm` context, then replace `xx(0x…)` calls with the strings. Built-in version configs are `gb["v1"]…gb["v9"]`.
- **Pack file:** `%APPDATA%\Incredibox\incredimods\<versionId>.json` = `{ "<path>": { "dataURL": "data:…;base64,…" } }`, plus an entry in `localmods.json` (`version, name, crew, modders, date, icon (dataURL), format, size, modio:false`). Paths: `app.json`, `anime/<name>.png` (HD) + `anime/<name>-ld.png` + `anime/<name>.json`, `anime/0_polo.png`/`0_polo-ld.png` (empty-slot beatboxer), `image/game-bck.jpg` (2048×800), `image/game-picto.png`, `image/home-screen.jpg` (2976×1420), `image/icon.jpg`, `image/crew.jpg`, `sound/<ogg|mp3>/<name>_a.<ext>` (+ `_b`).
- **app.json:** `looptime` ms, `bpm`, `totalframe` = frames for **two** loops (~24 fps; e.g. 4800 ms → 232), `animearray[{name,color,uniqsnd}]`. `uniqsnd:false` → engine alternates `<name>_a` / `<name>_b` and the anime JSON has `totalframe` frames (A then B); `uniqsnd:true` → one sound and `totalframe/2` frames.
- **Anime JSON / sheet:** `width` 164, `height` 380 (forced to 380 unless `version` ≥ 1), `headHeight`, optional `gap`. All coordinates are in **LD pixels**; the HD sheet is ×2. Sheet row 0 = [idle full body | body without head (drawn while playing) | black silhouette (mute overlay, alpha 0.7)]. Each `arrayFrame[i].prop = "x,y,dx,dy"` is the source top-left of a `width × headHeight` "head" crop drawn at `(dx,dy)` over the body. For full-body animation, set `headHeight = 380` and make the body cell transparent.
- **Picto sheet:** 20 × 136 px icons (HD 2720×272). Row 0 = normal, row 1 = icon "in use".
- **Polo sprite (`0_polo`, LD 656×480):** base 164×400 at (0,0), overlay silhouette at (164,0) (drawn with alpha, which is why polos look grey), eyelids at x=328 and eyes at x=492 (164×40 rows, `eyesTopY` 97). Geometry comes from `iy.polo` in the game JS.

## 3.0.3 Scratch (.sb3) → Incredimod Converter (Sprunki-style projects)
- **Location:** code is in `scripts/sb3-to-incredimod/` (see its README). Work folders such as `H:\source\incredibox-work\sprunke-kusoshi\` hold `src/` (the extracted `.sb3`), `out/` and `config.js`. Keep them **outside** the repo, because the `.sb3` and generated assets are third-party content. Pipeline: `node convert.js <project.sb3> --work <dir> [--install]` (= `prepare.js` → per phase `build-art.js` ∥ `build-audio.js` → `build-pack.js`). The single steps still work, each with `--work <dir>`. `configs/sprunke-kusoshi.js` is the reference config. The repo version was verified against the installed pack: all 68 images and JSON files are byte-identical, and the 40 ogg files decode to identical PCM (Ogg stream serials are random, so the bytes differ). The old `tools/` copy in that work folder is superseded.
- **Assumes:** sprites 1–20 are the characters in icon order, `Icons` has `NN-a` / `NN-c` costumes, characters use `Loop 1` / `Loop 2` broadcasts, and `Preview` holds the cover.
- **First conversion:** "Sprunke Kusoshi (Sprunk x Mesmerizer)" by treeguy2763 (Cocrea, open source `PUBLIC`; the user forked it and downloaded the `.sb3` themselves). Installed as incredimod `9483402`. Phase 1 (200 BPM, 4.8 s loop) only.
- **Timeline:** a mini Scratch interpreter runs each character's `Loop 1` / `Loop 2` broadcast hats at 30 fps (`wait` resumes at frame boundaries, non-warp `repeat` yields one frame per iteration, scripts are cut at `loopSec`). It records costume switches **and `sound_play`**, because the sound choice depends on globals (e.g. `Maj/Min` defaults to `Min` → Mr. Sun plays sounds 5/6, not 1/2). Stage variables seed the globals; `phase` is overridden.
- **Audio:** three cycles of Loop1/Loop2 starts are mixed (a sound that restarts cuts its previous instance, as in Scratch; tails of other sounds overlap into the next loop). The last cycle is split into `_a` / `_b` of exactly `looptime`, encoded as Vorbis.
- **Framing (user-approved 2026-11-19):** `scratch` mode maps the Cocrea slot (65 stage units wide) to 164 LD (`k = 164/65`). The character rotation center is at (82, 253) LD, fitted to a screenshot of the original. The user tried and rejected full body (too small) and Incredibox-style "head at the top" x1.8. They also tried the original red "FOCUS" panel as the empty slot and asked to go back to the **default Incredibox beatboxer** (`panelCostume: {}`).
- **Second conversion (2026-11-19): "Interbox V1: Subliminal" by Expensive_Chb** (Scratch; author given by the user, not recorded in the file) — `.sb3` saved with the **Gandi IDE** (`meta.platform = Gandi`). Work folder `H:\source\incredibox-work\interbox-subliminal\`, installed as incredimod **`9774514`** (108 files, 71.8 MB). Differences from Sprunke Kusoshi: sprites are `Beat/Effect/Melody/Voice 1–5`, no `phase` variable (one phase), Stage `Delay = 60/130*16` → `loopSec 7.385`, 130 BPM, 179 frames per loop; characters are size 70 and "go to Polo N" (slots 64 apart → `k = 164/64`); the placed costume is `0` (Effect 5: `GROWL 1`), not `idle`; the `Characters` list gates playback (the interpreter's `listItem` returns `1`). Converter changes for it: `timeline.js` picks the idle costume per character (override → `idle2` in phase 2 → `idle` → `0` → first costume), `build-art.js` supports `characters[i].dy`, `build-pack.js` takes `config.platform`. Effect 3 (`dy 58`) and Voice 3 (`dy 14`) are nudged down because their heads went above the 380 px frame. Sprunke Kusoshi timeline output is unchanged (diffed, phases 1 and 2). Credit: `author Expensive_Chb`, `platform 'Scratch / Gandi IDE'`, `source https://scratch.mit.edu/users/Expensive_Chb/`.
- **In-game feedback round 1 (user screenshot, 2026-11-19):** with `k = 164/64` the characters looked too large and the background looked cropped, with black bands on both sides. **Cause:** the game layout (`iy.canvas` baseW 1100 / baseH 430 / marge 200; `iy.polo`): sheets are drawn at `iq = (W/6.8)/164 = 0.986`, slots are `ix = (W - W/6.8 - 100)/6 = 139.7` px apart, and a sheet's top = `H - 380*iq + random(0..30)*iq` (`drawPoloY = hJ - drawH + poloGapY`), so the sheet bottom sits on the canvas bottom. One slot (64 units) is therefore 139.7 px, not 164 → `k = 139.7/64/0.986 = 2.213` (old 2.5625 was +16%). The Interbox backdrop SVGs are about 990 units wide (twice the 480×360 stage). Gandi uses the standard stage size; only the centre shows in Scratch. `drawCover` had fitted the whole SVG to the frame, including its black/transparent edges. **Fix:** `framing.slotUnits` (k from the game layout) and `background: {mode:'stage', slotY: 6}`. The backdrop is drawn with stage (0, slotY) at the canvas y of `charY`, at 2.183 canvas px per unit, so the canvas shows stage x ±252 and y −45…+152. Effect 3 `dy` is now 18 and Voice 3 needs none. Offline preview: compose `game-bck` + idle cells with the same formulas (PIL script). Not reproduced: `Flashlight(withgradient)` is a mouse-following dark vignette sprite. ## 3.0.4 Native PC 100-Icon / 10-Polo Engine Patch & Multi-Mod Builder (2026-11-19)
- **Route (b) succeeded — no third-party APK engine needed:** PC v1.2.9 `script.min.js` already iterates `lQ` (icon count) and `pQ` (polo count) in every game/audio/mix loop, with only 5 hardcoded constants/hooks. Routes (a) "write into a 100-character APK engine" and (c) "own minimal player" were not needed (see §3.3).
- **Engine patch (`modloader/engine-patch.js`, called from `main.js` before `src/elec-index.js`; marker `/*INCREDIBOX_MODLOADER_100P_V3*/` as the first line):** backs up the vanilla `src/js/script.min.js` once to `script.min.js.orig`, always patches **from `.orig`** (marker upgrades re-patch from it), writes via `.tmp` + rename, and applies 5 replacements that must each match **exactly once**:
  1. `unlock-icon-cap` — removes `>0x14?0x14:lQ` in `m2()` so `lQ = px.animearray.length`.
  2. `dynamic-nbpolo-and-recmaxloop` — in `pV()`, `pQ = 0x7` becomes `px.nbpolo > 0 ? px.nbpolo : 7`. The same expression sets `px.recmaxloop = Math.max(999, Math.ceil(9999000 / (px.looptime || 8000)))` (recording limit ≥ 9999 s / ≥ 999 loops for **every** version, vanilla included), `recminloop ||= 2`, and `recmintime ||= round(looptime s) × recminloop`.
  3. `polo-width-6.8` / 4. `polo-width-6.3` — in `window.onresize`, `aq = (pQ > 7 ? pQ - 0.2 : 6.8)` (and `pQ - 0.5 : 6.3`) and `ak *= aq / 6.8` (`6.3`): the polo width follows the polo count, and the effective stage height `ak` shrinks by the same ratio, so 10 polos keep the vanilla headroom instead of becoming smaller.
  5. `resize-picto-hook` — calls `window.__mlLayoutPcPictos(lQ, pQ)` right before `poloBlocGapX = av / 2` on every resize.
  - **Fail-safe:** if any pattern does not match exactly once (game update), nothing is written; an older patched version on disk is reverted to `.orig`, a vanilla script is left as is (`[EnginePatch] Skipping …` in the log). A patched script without `.orig` is left alone and is **never** copied to `.orig`.
  - **To change a patch:** edit `PATCHES` in `engine-patch.js`, bump the marker (`_V4`), and test offline: `patchEngineSource(<.orig text>)` must succeed and compile (`new vm.Script`). The installer and `setup-game.ps1` wipe `resources/app`, so a reinstall starts from a fresh vanilla script.
  - **Where the patterns live (decoded v1.2.9):** `qF()` builds the pictos (`ab = lP.length > 10 ? ceil(lP.length / 2) : 1000`, first half into `.pictoline.top`, rest into `.pictoline.bot`, via jQuery `.html()`), and is called once per game start from the init that also creates `qG()` polos. Each version opens through `app.html?v=<id>` (a full page load), so the extra `.pictoline.ml-extra` rows added by the renderer never survive into another version.
- **PC 100p layout (`modloader/renderer.js`, `window.__mlLayoutPcPictos`):** when `#box-picto .picto` count `> 20`, adds `html.ml-100p-mode` (`--box-top-height-int: 10`, `--box-bottom-height-int: 50`, stage `40%`) and arranges pictos into `ceil(N/20)` `.pictoline` rows of 20 icons with 5-icon group gaps, sized in real pixels from `#box-bottom` (22–68 px; no CSS `transform: scale`). The first switch into the mode dispatches one extra `resize` so the patched `onresize` recomputes with the new box heights. Standard ≤20-icon / 7-polo versions are untouched.
- **Multi-mod builder (`scripts/build-100p-mod.js`):** merges 20-character sources into one PC incredimod pack. Needs **ffmpeg (libvorbis)** and **Python 3 + Pillow** on PATH (checked before the build starts).

## 3.1 Conventions / Gotchas
- **Overlay HTML:** all mod / APK metadata (name, author, description, error, id) goes through `escapeHtml` in `modloader/renderer.js` before `innerHTML`. APK `app.js` names are third-party text.
- **Logging:** first log write per launch renames `Mods/modloader.log` → `Mods/modloader.prev.log` (keeps exactly one previous session).
- **`unpack-apk-mod.js` side effect:** rewrites `this.recmaxloop = N` → `999` in every `asset-v*/app.js` (recording limit) and blanks `cordova.js`.
- **Installing packs (`scripts/lib/common.js` `installIncredimod`, used by `import-apk.js`, sb3 `build-pack.js` and `build-100p-mod.js`):** copies `localmods.json` to `localmods.json.bak-<Date.now()>` first, upserts the entry by `version`, writes `<versionId>.json`, then keeps the newest 5 backups. Backups are ordered by the **time in the name** (both `bak-<ms>` and the older ISO `bak-2026-11-19T05-54-07-202Z` form), not by mtime: `copyFileSync` keeps the source's mtime. A `localmods.json` that does not parse throws (the backup is kept) instead of being replaced. All three tools refuse to install while `Incredibox*` is in `tasklist` (`isGameRunning`, `--force` overrides), because the running game rewrites `localmods.json`.
- **Line endings are mixed** in the working tree (most older files CRLF, some newer LF); git `autocrlf` normalizes them and warns "LF will be replaced by CRLF" — harmless. When editing with scripts, keep each file's existing ending. Compare deployed vs repo with `diff --strip-trailing-cr`.
- **Shell gotchas:** in Git Bash heredocs, backticks / `${…}` / `\\x` inside a script can break or get mangled; write such scripts to a file with the Write tool. Avoid `rm` on `$VAR` paths (the agent safety check blocks them); use `${VAR:?}` or literal paths.
- **APK screen scale vs pointer math (2026-11-19):** APK mode scales `body` with `transform: scale(apkScale)` (origin center), but APK engines compute positions from layout values (`offsetLeft`, `screenW`). Replay seek (`moveControlHead` in `main.min.js`) was off by `(1-scale)/2`: at 90% the leftmost click jumped to 5% (1:19 of a 26:14 mix) and the end was unreachable. `renderer.js` `patchReplaySeek()` replaces the global `window.moveControlHead` with a `getBoundingClientRect()`-based version (falls back to the original on error). Verified offline against the engine's own function (vm, scales 0.7/0.9/1). **Verified in game by the user (2026-11-19):** a 26:14 Armed replay now seeks to 0:00 from the left edge. Picto drag (`bouger(pageX, pageY)`) may have the same offset; it was not reported, so it is untouched.
- **Quick redeploy of loader only:** copy **all** `modloader\*.js` (including `engine-patch.js`) into `Modded\resources\app\modloader\` (game must be restarted). Full `setup-game.ps1` wipes and re-extracts `resources\app`.
